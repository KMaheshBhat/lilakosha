## Background

There are refine/scalpel steps that were developed organically as need arose.  Almost all of them iterate over the CDM records, mutate them, and save them back.  The mutation may be Inference or other types of data processing.  The scalpel steps are used to reverse the mutation applied by the refine steps.

### Observations

**1. Boundary-scoping efficiency differs sharply across refine steps.**

- `refine-cdm-language` pre-filters candidate files by `file.stem` against `start_uuid` / `stop_uuid` *before* opening or parsing JSON. This avoids deserializing out-of-range records entirely.
- `refine-cdm-html-to-markdown`, `refine-pippa-characters`, `refine-pippa-genre-theme`, `refine-pippa-grammar`, and `refine-pippa-safety-dials` all build the full file list first, then open every record, parse it into a `Document`, and compare the UUID *after* deserialization. For narrow ranges in large record sets this is significantly slower and more memory-intensive.

**2. Idempotency checks are tailored to business-logic requirements, not arbitrary.**

- `refine-pippa-characters` skips when a synthesized `character` item with `entity_id="user"` already exists, because character synthesis is intended to run once per document lifecycle.
- `refine-pippa-genre-theme` and `refine-pippa-safety-dials` skip when their target `categorization` categories are already present, because genre/theme/safety classifications are meant to be stable once computed.
- `refine-pippa-grammar` skips only when both `original` and `refine-pippa-grammar` variants exist on a `TurnItem`, because grammar revision is intentionally re-runnable only when the refined variant is absent.
- `refine-cdm-html-to-markdown` overwrites any existing `refine-cdm-html-to-markdown` variant in place, because Markdown conversion is idempotent by nature and the step is designed to refresh rather than skip.
- `refine-cdm-language` performs **no idempotency check** and re-detects language unconditionally; this reflects a deliberate choice to keep language categorization fresh across re-runs rather than cache it.

**3. Annotation hygiene varies.**

- `refine-cdm-html-to-markdown` explicitly calls `remove_annotation(document, "refine-cdm-html-to-markdown")` before `add_annotation(...)`, ensuring a clean re-run state.
- The remaining refine steps append annotations without removing prior ones, which can accumulate duplicate or stale annotation entries on repeated runs.

**4. Only the PIPPA inference steps implement a budget cap.**

- `refine-pippa-genre-theme`, `refine-pippa-grammar`, and `refine-pippa-safety-dials` support `max_inference_budget` and raise `InferenceBudgetExhausted` to terminate loops early.
- `refine-pippa-characters` tracks `inference_counter` but does not enforce a budget ceiling.
- `refine-cdm-language` and `refine-cdm-html-to-markdown` have no inference budget concept.

**5. Mutation granularity is split between document-level and item-level.**

- Document-level mutations (`language`, `characters`, `genre-theme`, `safety-dials`) append or replace top-level `CategorizationItem` / `CharacterItem` entries and update `document.meta`.
- Item-level mutations (`html-to-markdown`, `grammar`) touch `ContentVariant` collections on specific kinds (`narrative`, `turn`, etc.) inside `document.items`.

**6. The scalpel for characters supports additional source-related scoping.**

- `scalpel-pippa-characters` accepts `pc_names`, filtering by player-character name before purging. No other scalpel step implements source-related scoping.

**7. Error-handling posture is uniform but counts differ.**

- All refine steps log per-record exceptions and continue. `refine-cdm-html-to-markdown` and `refine-pippa-grammar` track `skipped_error_count`; the PIPPA inference steps track `skipped_range_count` plus inference budget counters.

### Ideal refine/scalpel Blueprint

The following blueprint distills the strongest patterns observed across the current implementations into a canonical refine-step template:

```text
run(config):
    1. Resolve volumes & records_dir. Exit early if missing.
    2. Extract parameters with `.get(..., default)` fallbacks.
       - start_uuid / stop_uuid
       - target definitions (kind + preferred variant order)
       - optional: max_inference_budget, rpm, temperature, max_tokens
    3. VALIDATE targets against SUPPORTED_KINDS set immediately; fail fast.
    4. PRE-FILTER record_files by file.stem vs start_uuid/stop_uuid BEFORE opening.
       - This is the single highest-impact optimization seen across the steps.
    5. Initialize counters: processed, skipped_range, errors, budget_used.
    6. For each pre-filtered file_path:
       a. Parse Document.model_validate_json.
       b. IDEMPOTENCY CHECK appropriate to mutation type:
          - For variant replacement: check existing variant name(s).
          - For categorization: check existing category/kind.
          - For inference: check existing annotation or item marker.
          If already applied, skip or overwrite deterministically.
       c. MUTATE minimally and locally:
          - Preserve `original` variant when adding refined variants.
          - Use ContentVariant.model_copy(deep=True) for safe replacement.
          - For document-level additions, append CategorizationItem/CharacterItem.
       d. ANNOTATION HYGIENE:
          - Call remove_annotation(document, STEP_NAME) before add_annotation(...).
          - Include reasoning/model metadata when available.
       e. update_meta(document) exactly once after all mutations.
       f. Write file only if doc_modified is True.
       g. Catch per-record exceptions, increment error counter, continue.
    7. Log summary: processed, skipped_range, errors, budget_used.
```

**Key principles the blueprint enforces:**

- **Pre-filter over post-filter**: Avoid parsing out-of-range documents.
- **Fail-fast validation**: Check target kinds and parameters before entering the loop.
- **Idempotency as a design decision**: Every refine step should declare its re-run behavior explicitly—skip if already applied, overwrite in place, or always recompute—rather than leaving it implicit. This makes the step's lifecycle intent clear and prevents accidental duplication or annotation drift.
- **Single write per record**: Mutate in memory, update meta once, write once.
- **Annotation clean-up**: Remove prior step annotations before re-adding to prevent annotation drift.
- **Budget awareness**: Inference steps should support `max_inference_budget` and graceful termination.
- **Counters for observability**: Track processed, skipped-range, skipped-idempotent, and error counts separately.

A matching scalpel blueprint would mirror the same pre-filtering and annotation-hygiene discipline, but instead of mutating it would surgically remove only the artifacts introduced by its paired refine step (specific variant names, category values, or item kinds) and then write back only when a removal occurred.

## Recommendation

The following changes are recommended to bring each refine/scalpel pair in line with the **Ideal refine/scalpel Blueprint**.  Each subsection lists the gap(s) observed and the concrete adjustment required.

### 1. `refine-cdm-html-to-markdown` + `scalpel-cdm-html-to-markdown`

| Blueprint Principle | Status | Recommended Change |
|---------------------|--------|--------------------|
| Pre-filter over post-filter | **Gap** | Move the `start_uuid` / `stop_uuid` filter to operate on `record_files` by `file.stem` *before* the `for record_path in tqdm(...)` loop. This avoids opening and parsing out-of-range JSON files. |
| Fail-fast validation | **OK** | `SUPPORTED_CONTENT_KINDS` validation is already performed before iteration. |
| Idempotency as a design decision | **OK** | Overwrite-in-place behavior is explicit and appropriate for idempotent Markdown conversion. |
| Single write per record | **OK** | `doc_modified` flag is used; writes only occur when a variant is changed. |
| Annotation clean-up | **OK** | `remove_annotation(...)` is called before `add_annotation(...)`. |
| Budget awareness | **N/A** | No inference involved. |
| Counters for observability | **OK** | `processed_count` and `skipped_error_count` are tracked. |

**Summary of changes:** Add pre-filtering by `file.stem`.
